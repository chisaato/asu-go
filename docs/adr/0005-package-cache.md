# ADR 0005：只共享包文件的构建缓存

- 状态：已采纳
- 日期：2026-10-28

## 决策

利用现有 Runtime put_archive/get_archive，在 Create/Start 之间向镜像 `WorkingDir/dl` 播种包，成功取回产物后回收包。共享目录按去除 digest 的镜像引用清洗分区；仅接受非空普通 `.apk` / `.ipk`，同目录临时文件和 rename 原子发布，同名跳过。索引始终由各任务自行拉取；自定义 repositories 禁用缓存，失败不回收，缓存异常仅告警。

默认启用、上限 20 GiB，Cleaner 按文件 mtime 近似 LRU 淘汰，播种更新 mtime；同一个服务实例共用互斥锁，避免播种、发布和淘汰相互干扰。多进程共享写不在支持范围。默认开启 `make image V=s`，另输出阶段整数秒耗时与构建信息头。

## 被否方案

- **bind mount 共享可写 dl**：并发更新索引/签名的安全性没有证明，且引入宿主 UID、SELinux 和 rootless 映射问题；归档复制保留 Runtime 无宿主路径的抽象。
- **共享索引**：apk 的 4 小时索引 TTL 可使 snapshot 选到旧版本；opkg 的 lists/签名同名更新也有竞争。不以“缓存包”为由冻结索引。
- **共享整个 WORKDIR、build_dir、tmp 或 packages**：构建中间状态不可跨任务共享，且会遮蔽镜像自带本地仓库。

## 代价与边界

每次任务复制全部同镜像缓存包，增加归档 I/O；不预测本次依赖。容量周期淘汰而非硬配额，零容量在下轮清理时删除包。镜像 tag 重用沿用相同仓库，实际包仍由包管理器验证/选取；清洗字符可能形成同键，不作为安全域隔离。失败下载绝不发布到共享仓库。
